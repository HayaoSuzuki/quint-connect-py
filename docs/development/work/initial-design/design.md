# Issue #1 の設計

Quint の状態列を Python 実装の公開 API に再生し、各操作の直後にモデルの期待値と実装の実測値を照合する。公式 Rust crate 向けの Quint モデルや ITF を Python でも使えるようにする。利用者は Python のテスト関数から `run()` または `replay()` を呼ぶ。[Issue #1](https://github.com/HayaoSuzuki/quint-connect-py/issues/1) · [Rust 版の API](https://docs.rs/quint-connect/0.1.2/quint_connect/)

## 対象と実行環境

| 項目 | 初版の範囲 |
| --- | --- |
| Python | GIL 有効の CPython 3.14 と 3.15 |
| Python の必須依存 | 追加の Python パッケージはゼロ。pytest、pytest-xdist、Hypothesis は開発と利用例で使う |
| 生成 | 利用者が指定した Quint 0.34.0 の `quint run --mbt` と `quint test`。Rust と TypeScript の両バックエンドで検証する |
| 再生 | 上記のコマンドが生成した有限の ITF。インストール済みのパッケージからオフラインで実行できる |
| 配布 | Maturin で `quint-connect-py` のネイティブ wheel と sdist を作る。import 名は `quint_connect`。公開設定と PyPI への公開はリリース時に行う |

Quint の実行ファイルとバージョンは利用者が管理する。バックエンドの省略時は Quint の既定値を使う。Quint の実行を伴う試験では、Rust 評価器を必要に応じて事前配置する。[Quint 0.34.0 の CLI](https://github.com/quint-co/quint/blob/v0.34.0/quint/src/cli.ts) · [Rust 評価器の取得処理](https://github.com/quint-co/quint/blob/v0.34.0/quint/src/rust/binaryManager.ts)

TLC などによるモデル検査、操作列自体の縮小、pytest の自動登録は別の作業とする。Hypothesis を使う例では `@given` が選んだ seed をそのまま `run()` に渡す。テストが縮小する入力は seed である。

## 公開 API

`run()` の第1引数は `Simulation` または `NamedTest`。どちらもモデルのパスを受け取り、必要に応じてメインモジュール名を指定できる。`Simulation` では初期化とステップのオペレーター名、生成件数、サンプル上限、各履歴のステップ上限を指定できる。`NamedTest` ではテスト名とサンプル上限を指定できる。テスト名は文字列として完全一致で選ぶ。

両関数は第2引数にドライバーのファクトリーを取る。`step(action)` には操作名と名前付き引数を渡す。ドライバーは実装の公開 API を呼び、`observe()` が比較対象の実測値を返す。ステップ 0 でもこの順で呼ぶため、初期化操作は `step()` で処理する。

```python
from quint_connect import Simulation, replay, run

run(
    Simulation("counter.qnt", n_traces=10),
    CounterDriver,
    quint="/path/to/quint",
    seed=42,
    state_path=("count",),
)
replay("saved.itf.json", CounterDriver, state_path=("count",))
```

`replay()` はパス一つまたはパスの列を取り、指定順に処理する。どちらの関数も `action_path` と `state_path` をキーワード引数に取り、フィールド名の列として受け取る。成功時の戻り値は `None` とする。

`run()` は `0 <= seed < 2**64` の整数を受け取る。省略時は呼び出しごとに Rust 側で生成し、実際に使った seed を生成トレースの状態不一致の診断に含める。既定のシミュレーション件数を 1 とし、サンプル上限の省略時には要求件数を明示して Quint に渡す。これらの既定値は設計案で定めた。`--seed` 指定時の Quint 既定値は、必要なサンプル数に達しないことがある。[Quint 0.34.0 の CLI](https://github.com/quint-co/quint/blob/v0.34.0/quint/src/cli.ts)

シミュレーションでは `n_traces > 0`、明示した `max_samples >= n_traces`、明示した `max_steps >= 0` を要求する。`max_steps=0` では初期状態だけを生成する。名前付きテストでは明示した `max_samples > 0` を要求し、省略時は Quint の既定値を使う。Quint 0.34.0 の名前付きテストでは上限に 0 を渡したときの挙動が評価器によって異なるため、両モードとも上限を起動前に検証する。Quint CLI が件数と上限を JavaScript の数値として読むため、`n_traces`、`max_samples`、`max_steps` の最大値は正確に表せる整数の範囲内で `2**53 - 1` とする。[Quint 0.34.0 の CLI 引数定義](https://github.com/quint-co/quint/blob/v0.34.0/quint/src/cli.ts#L212)

## ITF の検証と照合

一つの ITF を読み、全ステップを検証してから、その ITF のドライバーを生成する。各ステップから操作名、名前付き引数、期待値を取り出す。ステップ番号は `states` の配列位置を 0 から数える。メタデータの `index` は再生順を決める材料にしない。`vars` は文字列の配列で、各状態は宣言された変数を持つ。Quint 0.34.0 が出力する `vars` の重複は許容する。JSON オブジェクトはエスケープを展開した名前で重複を検出する。`loop` を含むトレースはエラーにする。[Quint 0.34.0 の ITF 実装](https://github.com/quint-co/quint/blob/v0.34.0/quint/src/itf.ts)

ファイルを UTF-8 と JSON の順に検証する。ITF 入力では先頭の BOM と、対になっていないサロゲートのエスケープを拒否する。文字列では、UTF-8 で直接記述した文字と同じ文字を表すエスケープを、同じ Unicode スカラー値の列に変換する。操作名、フィールド名、文字列値の照合はその列で行う。たとえば合成済みの文字と基底文字に結合文字を続けた綴りが、異なるコードポイント列なら区別する。[RFC 3629 §4](https://www.rfc-editor.org/rfc/rfc3629#section-4) · [RFC 8259 §8](https://www.rfc-editor.org/rfc/rfc8259#section-8)

- `action_path` を指定した場合、そのパスの sum type のタグを操作名とし、ペイロードのレコードを引数とする。空タプルは引数なしを表す。名前付きテストにはこの指定が必要となる。
- `action_path` の省略時は `mbt::actionTaken` と `mbt::nondetPicks` から読み取る。有効な操作名はステップ 0 にも必要となる。
- どちらの取得元でも、各引数の直下にある正規形の `Some(v)` を一段だけ外し、正規形の `None` は引数ごと省く。この位置で正規形と同じ構造を持つレコードは Option として解釈する。[Rust 版の操作と引数の抽出](https://github.com/quint-co/quint-connect/blob/main/connect/src/driver/step.rs)
- `state_path` で指定した値を比較する。省略時は、状態レコードから ITF と MBT のメタデータを除いた値を比較する。モデルの操作記録フィールドは残る。
- モデル値の整数は `#bigint` の文字列として読み、ASCII の十進桁と先頭のマイナスを受け付ける。整数、真偽値、文字列、リスト、タプル、レコードは Python の対応する組み込み型に変換する。集合は `QuintSet(values)`、マップは `QuintMap(entries)` で表す。引数は要素の列またはキーと値の組の列で、レコードやリストを要素やキーにできる。ドライバーもこれらの型で集合とマップを返す。`dict` はレコードを表す。集合の要素順とマップの項目順を無視し、リストとタプルの順序は比較する。集合の等価な要素は一つにまとめる。マップで等価なキーが重複すればトレースエラーとする。真偽値と整数、レコードとマップなど、型の区別は再帰的に維持する。
- `tag` と `value` を含む値は、操作と Option の解釈位置を除きレコードとして扱う。比較対象または引数の内部にある `#unserializable` は位置付きのトレースエラーとする。選択したパスの外側は値の照合から外れる。[ITF の値表現](https://apalache-mc.org/docs/adr/015adr-trace.html#the-itf-format)

一つの ITF の全ステップが一致してから次の ITF を開く。`replay()` は利用者が指定したシンボリックリンクをたどる。同じ ITF を異なる名前で指定した場合、指定順に読み取り、各入力のドライバーを生成する。ドライバーのファクトリーには呼び出すたびに新しい実装状態を用意する契約がある。実装が外部 DB や作業ディレクトリを使うときは、ファクトリーがトレースに対応するリソースを用意する。

## 失敗と成果物

| 条件 | 呼び出し元への結果 |
| --- | --- |
| seed が範囲外、生成件数や上限が指定範囲外、または名前付きテストで操作パスを省略 | 作業先の確保や CLI の起動に進む前に Python の `ValueError` |
| 名前で指定した Quint が `PATH` 上で見つからない、または候補を実行できない | 作業先を確保する前に、コマンド名または最初に拒否された候補とその原因を報告する |
| 作業先の確保後に Quint を起動できない | 実際の seed と起動に失敗した原因を持つ CLI エラー |
| Quint が非ゼロの終了コードまたはシグナルで終了 | 実際の seed、終了コードまたはシグナル番号、標準出力と標準エラーの元バイト列を持つ CLI エラー。部分出力の ITF は再生しない |
| Quint が成功して ITF が 0 件、渡されたパスが 0 件、または ITF の状態が 0 件 | 発生箇所を示す空トレースのエラー |
| シミュレーションで 1 件以上出たが要求数に不足 | 要求件数と出力件数を持つ件数不足エラー |
| 保存済み ITF のパスもしくは別名の参照先が存在しない、別名が循環する、または読み取りに失敗 | 利用者が指定したパスと原因を示すトレースエラー |
| Quint の正常終了後に作業先の一覧取得が失敗 | 作業先と元の原因を示すエラー。取得済みの項目の再生にも進まない |
| 生成済み ITF の読み取りが失敗 | 対象のファイルと原因を示すトレースエラー。そのファイルのドライバーを生成する前に止まる |
| ITF の UTF-8、JSON、構造、パス、引数または期待値を解釈できない | ファイルと、該当する場合はステップを特定できるトレースエラー |
| ファクトリー、`step()`、`observe()` が失敗、または `observe()` が対象外の型を返す | 段階と元の例外を保持するドライバーエラー |
| 作業ディレクトリの確保に失敗、または再生結果が成功だった呼び出しの掃除に失敗 | 失敗した段階と元の原因を示す作業ディレクトリのエラー |
| 観測値が期待値と異なる | `AssertionError` のサブクラス。トレース、ステップ番号、操作、引数、期待値、実測値を属性に持つ |

`run()` は呼び出しごとに専用の作業ディレクトリを確保する。Quint はそのディレクトリで起動し、両モードで `trace_{seq}.itf.json` を生成する。モデルや実行ファイルの相対パスは、呼び出し時に取得したカレントディレクトリを基準に解決する。実行ファイルを名前だけで指定した場合も、起動前に呼び出し元の環境で探索する。相対または空の `PATH` 項目が指す先の基準も呼び出し元のカレントディレクトリとする。記載順に最初の実行可能な候補を選ぶ。見つからなければ、候補がすべて存在しない場合と、存在する候補が実行できない場合を区別する。後者では最初に拒否された候補と原因を保持する。選んだ実行ファイルの起動に失敗した場合は、探索を再開せずその失敗を返す。子プロセスのカレントディレクトリには専用の作業先を使う。

起動失敗と終了失敗では、一覧取得や再生に進む前に予約済みの作業先を掃除する。Quint が正常終了し、作業先の一覧取得が完了してから、標準の出力名に一致する通常ファイルを、十進連番の数値順に読み取る。同じ形式の名前を持つディレクトリ、シンボリックリンク、特殊ファイルは件数から除く。通常ファイルの読み取り失敗は対象ファイルの診断として返す。名前付きテストでは `max_samples` を試行上限とし、成功して得られた一件以上の ITF を処理する。再生は表の失敗が最初に確定した時点で止まり、後続ステップや次のトレースは実行されない。

生成した ITF で状態不一致が起きた場合、失敗した一件の元のバイト列を成果物として残す。例外は実際の seed と成果物のパスを保持する。そのパスを `replay()` に渡せば、通常の保存済み ITF と同じ手順で読む。成果物の親ディレクトリを利用者が指定できる。省略時はシステムの一時ディレクトリを使う。どちらの場合も成果物のサブディレクトリは、コピーを始める前に排他的に確保する。同じ親ディレクトリで候補名が衝突した場合は、以前の成果物を維持して次の候補を試す。候補が尽きた場合や確保の I/O に失敗した場合は、元の状態不一致に保存先の候補と失敗原因を添える。成果物の一時ファイルに全バイトを書いてから公開する。別の再生が公開前に保存先を開けばファイル未発見になり、公開後は作業先の掃除中でも全バイトを読める。書き込みまたは公開に失敗した場合は、状態不一致に保存エラーの原因を添える。生成用の作業ディレクトリは呼び出しの終了時に掃除する。作業先にシンボリックリンクがあればリンク自身を削除する。別の呼び出しの成果物を指すリンクでも、参照先を削除しない。先に失敗が確定していれば、その例外を維持し、掃除の失敗は付記する。

## Rust と Python の境界

ITF の検証、値の照合、再生順、Quint の起動、作業先と成果物の管理は Rust で実装する。PyO3 のモジュールが Python の引数と値を Rust の型へ変換し、トレースごとにファクトリーを呼び、ドライバーの `step()` と `observe()` を実行する。例外の型や属性もこの境界で設定する。Python 側は公開名の再エクスポートと型情報を定義する。[PyO3 の Python 呼び出し](https://github.com/pyo3/pyo3/blob/main/guide/src/python-from-rust/function-calls.md)

公式 crate の公開ランナーは一つのドライバーを複数の履歴に使い、保存済み ITF の再生処理は非公開である。既存のランナーを直接使うには、上流でファクトリーと再生の API を変更する必要がある。初版ではこのリポジトリに合意済みの再生処理を実装し、公式モデルとその ITF を互換性試験の入力にする。[公式 crate のランナー](https://github.com/quint-co/quint-connect/blob/3b9eab8d817cbcd6de64ca1b05a20f18b96797ef/connect/src/runner/mod.rs)

一つのプラットフォーム向け wheel で CPython 3.14 と 3.15 に対応するため、初版は PyO3 の `abi3-py314` を使う。Maturin は Rust 拡張と Python の型情報を一つのパッケージに含める。wheel をインストールした利用者は、そのプラットフォームの Python から直接 import できる。[PyO3 の stable ABI](https://pyo3.rs/main/features#features-to-select-the-target-abi) · [Maturin のパッケージ構成](https://www.maturin.rs/project_layout.html)

## モジュールの責務

| 責務 | 他のモジュールから見える情報 |
| --- | --- |
| Quint の起動と生成物の管理 | モード別の設定、実行結果、数値順に並んだファイル、保存結果 |
| ITF の検証、変換、値の照合 | 指定されたパスから取り出した、操作と期待値の順序付きの列 |
| 再生と診断 | 検証済みステップ、ドライバーの操作と観測、最初に確定した失敗 |
| Python バインディング | 公開関数・型、コールバック、Python の値と例外 |

ITF は一件ずつ検証と変換を済ませ、処理済みのステップ列を共通の再生処理に渡す。この方式では、ドライバーを生成する前に後続ステップの形式エラーを検出でき、ITF 値の変換は一回で済む。検討したもう一つの方式は、先に全ステップを検証し、再生中に同じ ITF から値を取り出す構成だった。後者では、検証時と再生時の整合性を管理し、変換を二度行う必要がある。初版では一つのトレースに収まる処理済みステップ列を保持する方式を採る。

## Quint モデルと実装の対応

[Quint の実行可能な仕様](../../../../spec/quint_connect.qnt) は各呼び出しの状態と共有のファイル状態を持ち、同じ選択パスを呼び出し内の全トレースに適用する。CLI 引数と出力順、UTF-8 と JSON の構文解析、ITF の変換と複合値の等値性、保存と掃除を別モジュールに置く。生成された ITF、利用者が指定したパス、保存した成果物は、いずれも元のバイト列を同じ処理に渡す。CLI の候補が実行可能かどうか、プロセスの起動・終了結果、一覧・読み取り・成果物ディレクトリ確保・コピー・公開・掃除の I/O 結果は、外部から与える。各段階で外部の応答を受け取って処理を進めると、呼び出し全体の残り作業を表す順序付きの量が遷移ごとに減少する。ドライバーの実測値も外部から与える。二件の呼び出しで生成と再生の進行を調べ、[四件の呼び出し](../../../../spec/quint_parallel.qnt)では作業先が同時に存在する状態で分離を確認する。[モデルの境界](spec-review.md#境界)

| モデルで確認する性質 | Python の対応する試験 |
| --- | --- |
| 生成失敗、空、件数不足ではドライバーを生成しない | CLI の失敗、出力ゼロ、件数不足を個別に再現する |
| 保存済み ITF を指定順に読み、読めないファイルと不一致を該当パスで報告する | 存在しないファイル、読み取り失敗、二件目の破損、同じパスの二回指定を確認する |
| UTF-8、JSON、ITF の各段階で入力を検証する | 同じ文字の直接記述とエスケープ、展開後の同名キー、構文不正と値表現の不正を確認する |
| 検証済みトレースごとにドライバーを生成し、0 番目から順に操作と観測を行う | 壊れた末尾、二件の ITF、ステップ 0 の操作名と観測順を確認する |
| 最初の不一致またはドライバーの失敗で再生を停止する | 一つの操作を省くドライバーと、各段階で例外を送出するドライバーを使う |
| 生成した ITF の不一致では元の履歴を保存し、保存に失敗しても診断が残る | 保存前後のバイト列を比較し、`replay()` で同じ不一致を確認する。保存失敗も再現する |
| 作業先の確保に失敗すれば生成を始めず、掃除に失敗しても先に確定した失敗を維持する | 作業先の確保と掃除の失敗を注入し、失敗の優先順と付記を確認する |
| CLI の成功後に一覧を取得してから生成されたファイルを読む。失敗した I/O の対象と原因を保持する | 一覧取得と二件目の読み取りに失敗させ、掃除の失敗を付記する場合も確認する |
| 相対パスの基準は呼び出し元で、子プロセスは予約した作業先を使う | 呼び出し元と子プロセスのディレクトリを変え、相対指定と名前指定で実行する |
| 生成されたファイルを名前の数値順に読み、保存後の同じバイト列から同じ不一致を得る | 両バックエンドの実出力を読み、保存前後のバイト列とエラーの属性を比較する |
| 呼び出し間でドライバー、作業先、成果物を共有しない | `pytest -n 2 --dist=each` でモデル、seed、成果物の親ディレクトリを共有し、各ワーカーの成果物が独立して再生できることを確認する |

Quint では段階ごとに `quint typecheck` と `quint run` を実行する。主要な遷移に到達するサンプルと、上表の不変条件を確認する。進行順が決まる代表例は別の `*_test.qnt` に記録する。実行結果は[仕様レビュー](spec-review.md)に、各テストが対応する遷移と不変条件は[Python 実装計画](plan.md)に記録した。Quint の実行履歴から、Rust 実装と照合する入力と期待結果を生成する。[照合データの仕様](../../../../spec/fixtures/README.md)
